# Refining Sect｜炼器宗

> 以中国五行为基础，围绕资源开发、阵法轮转、生产自动化与灵石贸易展开的网页放置增量游戏。

## 项目简介

在《炼器宗》中，玩家将扮演炼器宗的一名内门弟子。主角获得了一处属于自己的宅院，以及一张简陋的纸质炼器阵图。宅院附近分布着泥沼、灵泉、丛林、矿洞、沼井、矿脉与熔岩口七处资源地点，但最初的主角既没有成熟的生产设施，也没有取之不尽的灵气。

玩家需要亲自采集和搬运材料，利用五行之间的相生相克关系取得新的资源，逐步将纸上阵图拓印到宅院地面，并建设一座能够自行采集、加工、输送和调度资源的五行炼器大阵。

游戏的成长不只表现为数字变大，也表现为劳动方式的改变：

```text
肩扛手提
  → 资源点自动采集
  → 材料就地加工
  → 五行线路自动输送
  → 整座炼器阵自行调度与生产
```

## 核心玩法

### 五行轮转

五行炼器阵以金、木、水、火、土五种灵气维持运转。

- 相生用于生成、延续和推动生产。
- 相克用于开采、切割、熔炼、淬火与材料加工。
- 五种灵气能够在阵眼和资源点之间流动，形成可以观察和调整的生产线路。
- 阵法动画将忠实呈现资源的真实流向、缺料、堵塞与过载，而非作为与数值无关的装饰。

### 质料、转化与归元

世界观以质能守恒、五行转化与可见损耗为设定；游戏运行采用逐次结算，不把整条生产循环的净收益当作守恒校验对象。M02只定义金属、木头、水、火、泥土五种基础资源和金、木、水、火、土五种属性灵气；基础火以可流动、会冷却的地火为实物形态，与火生灵气分开记账。器物、灵石、金液等加工状态不会反向扩张这十种基本量。单次纯五行转化不会超过100%的效率；合成与归元各自按配方结算，允许玩家通过高产替代配方和逐级归元取得净增的下级材料。

实体质料可以归元为灵气，灵气也可以作为做功能力，用于从真实资源点获取材料。例如：

```text
泥土
  → 土生金，炼出金生灵气
  → 金克木，以金气砍伐树木
  → 获得木头
  → 制作水桶
  → 前往灵泉取水
```

灵气灵活却容易逸散，实体材料笨重却便于长期保存。玩家需要在即时生产、物资储备和运输成本之间作出选择。

### 生产自动化

七处资源地点提供五行原料。其中矿洞和沼井用于过渡教学，不能建设固定设施；泥沼、丛林、灵泉、矿脉和熔岩口可逐步接入固定生产网络。

五处可建设资源点各有一个负责高效取得基础资源的固定输出设施；玩家通过升级、持续供灵、维护和疏通提高它的能力，而不是无限复制同类采集设施。玩家还可在这些地点建设固定炼器阵和本地仓储，布设可拆的聚灵阵及外围阵法，利用分流滑条管理基础资源与当地属性灵气的去向，再通过导流槽、传送带或天舟组织跨地点物流。例如，将熔岩口产出的地火引至矿脉，可以通过“火克金”就地熔炼矿石，再利用耐火导流槽将金液送回宅院。

自动化不会凭空创造资源。每一条线路都具有真实的输入、输出、容量和机会成本；资源点的天然灵脉流量也需要在材料生产、灵石灌注与线路维持之间分配。

### 灵石与商业

当五行灵气齐备后，炼器阵可以在中央凝结空白灵石。空白灵石是可交易的生产资料，但只有完成属性灌注与封灵的灵石，才是宗门通行的硬通货。

属性灵石既可以用于交易，也可以作为配方、建设或供能投入。灵石制成后可以永久保存；作为供能物提交后不可取回，不存在部分放能和剩余电量。同属性低品灵石可以按相邻品级`16:1`单向替代高品需求，高品灵石不能直接向下替代低品需求。

炼器阵越高品，资源转化损耗越低，但灌注灵石的基础损耗反而越高。玩家可以在地面固定炼器阵外组合不同品级的外围阵法，分别改善转化、归元、供能、耗时与跨地点灵气供应；纸质炼器阵不获得外围阵法加成。

灵石分为下品、中品、上品和天品。相邻品级采用不对称兑换：

```text
1块中品属性灵石 → 8块同属性下品灵石
12块同属性下品灵石 → 1块中品属性灵石
```

这种市场兑换与`16:1`的配方替代是两套机制：兑换产生可以保存和交易的高品灵石，替代只满足当前投入。价差体现了高位炼器师对高品灵石生产与兑换渠道的垄断。

宗门交易以配方的标准属性灵气成本评价器物，不把基础资源计入隐藏估值；成交至少需要一块任意属性的下品灵石。玩家可以依靠炼器生产发展，也可以通过天然灌注、代工委托、商人议价和品级兑换完成原始积累。当前整体市场货源和需求视为无限，单个商人对大批供货会提出批发价。

## 表现形式

《炼器宗》计划采用二维网页界面：

- 使用像素画 Banner 与文字呈现宅院、资源点、人物和宗门事件。
- 使用可交互的阵法图表现五行炼器阵与生产线路。
- 通过阵纹轮转、灵气流动、阵眼明灭和器物成形，表现自动化机器般的运行过程。
- 不追求高成本的3D场景，将开发重点放在系统深度、反馈清晰度与长期成长体验上。

## 设计方向

本项目希望支持多种可以相互混合的玩法：

- 建设高吞吐量五行生产线的自动化玩法。
- 研究材料、配方和阵法组合的炼器玩法。
- 开发资源点并利用天然灵脉的经营玩法。
- 承接师弟师妹灌注委托的代工玩法。
- 利用品级、属性、时间与地域价差的商业玩法。

玩家不需要在开局永久选择职业。生产方式、资源分配与商业策略本身，将逐渐塑造每一处宅院不同的发展道路。

## 技术方向

当前计划采用以下技术路线：

- Svelte 5
- TypeScript
- Vite
- SVG 与 CSS 动画
- `decimal.js`
- Vitest
- Playwright

游戏模拟、界面渲染与动画表现将彼此分离。动画帧率不会决定资源产量，存档也将从第一版开始采用明确的版本与迁移机制。

## 本地开发

本地已在 Node.js 24 与 pnpm 11.8.0 下验证。安装依赖后启动桌面浏览器页面：

```sh
pnpm install
pnpm dev
```

启动后打开终端输出的本地地址（通常为 `http://localhost:5173/`）。不要直接双击 `index.html` 或 `dist/index.html`：浏览器通过 `file://` 打开项目文件时不会加载 Vite 提供的模块，因此页面会显示启动说明。此阶段不需要游戏后端。

本地验证命令：

```sh
pnpm check         # Svelte 与 TypeScript 检查
pnpm test          # 规则单元测试
pnpm test:browser  # 浏览器测试；首次使用需安装 Playwright Chromium
pnpm build         # 检查并构建页面
```

首次安装浏览器测试环境时运行 `pnpm exec playwright install chromium`。当前页面面向桌面浏览器，移动端布局及移动平台文件导入导出不在首轮范围内。

存档保存在当前浏览器的 `localStorage` 中，结构版本与页面版本分别管理。无法识别的存档不会被自动覆盖；页面会显示原始内容供复制备份。首个代码版本及后续版本由 `pnpm version:stamp <major|module|component|feature>` 按 [版本号规则](docs/VERSIONING.md) 生成，不手工填写代码行数。
