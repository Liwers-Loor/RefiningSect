# 《炼器宗》开发路线图

## 文档目的

本文档记录《炼器宗》的长期版本目标和各阶段的玩家体验承诺。路线图描述的是方向与验收边界，不承诺具体发布日期；实际开发顺序可以根据验证结果调整，但不得在没有记录原因的情况下改变大版本目标。

版本号的生成和递进规则见 [VERSIONING.md](VERSIONING.md)。

## 总体路线

| 阶段 | 核心定位 | 玩家体验承诺 |
| --- | --- | --- |
| v1.0以前 | 游戏基础功能开发 | 建立可持续扩展的五行模拟、资源、自动化、经济和任务基础 |
| v1.0 | 首个完整流程 | 从内门弟子成长为宗门长老；弱探索、中等解谜、强主线 |
| v2.0 | 多道路与多结局 | 提供多条主线及与关键选择对应的多个结局 |
| v3.0 | 交织因果 | 加入互相影响的多支线、中等探索和强解谜内容 |
| v4.0 | 动态宗门世界 | 加入天气、大事件、可切换主线和其他宗门联谊活动 |
| v5.0 | 修仙界全景 | 展开暗线、复杂结局和修仙界大地图，并建设B/S架构与Electron桌面版本 |

## v1.0以前：基础功能开发

v1.0以前不追求一次完成所有内容，而是依次证明游戏的核心循环能够成立。以下是开发阶段，不是对外版本号的第二至第四段，也不要求与版本计数一一对应。

### 仓库与工程基础

- 建立仓库治理、文档权威和本地验证门禁。
- 搭建Svelte、TypeScript与Vite基础项目。
- 分离游戏模拟、界面渲染和动画表现。
- 建立确定性时间推进、数值类型与版本化存档。
- 建立单元测试、浏览器测试和本地构建入口。

完成标志：项目能够在本地安装、检查、测试和构建；空白存档能够可靠保存、读取和迁移。

### 纸质炼器阵与首个资源闭环

- 获得纸质炼器阵与基础配方。
- 从宅院泥土开始进行手工采集和转化。
- 完成“泥土→金生灵气→砍树→木头→水桶→泉水”的首个垂直切片。
- 使用像素画Banner和文字呈现早期场景与任务。

完成标志：新玩家无需开发者指引即可走通首个资源闭环，刷新页面后进度保持正确。

### 五行资源与守恒规则

- 开放灵泉、地火、丛林、矿脉和泥沼五处资源点。
- 实现归元、相生、相克与成器。
- 建立五行灵气、二转质料和基础构件体系。
- 实现转化效率上限、灵气逸散和实体材料储存。
- 保证玩家不会因耗尽启动资源而进入不可恢复的软锁。

完成标志：五处资源点均可被发现、开发和利用，核心转化始终遵循既定守恒规则。

### 地面炼器阵与阵法表现

- 将纸质阵图拓印为宅院中的地面炼器阵。
- 实现五个阵眼、外圈相生线路、内部相克线路和中央凝结区域。
- 实现阵眼效率、容量、损耗与五行轮转。
- 加入四象稳灵阵等外围阵法。
- 使阵纹、灵气流动、缺料、堵塞和停机表现与真实模拟状态一致。

完成标志：玩家能够从阵法表现中读懂当前生产状态，动画不参与资源计算。

### 自动化生产网络

- 建设资源点自动采集设施。
- 将材料加工从宅院逐步迁移到资源点。
- 建立仓储、吞吐量、运输容器、导流槽和五行线路。
- 实现资源优先级、线路分配和离线结算。
- 允许天然灵脉流量在材料生产、灵石灌注和线路维持之间分配。

完成标志：玩家可以从肩扛手提发展出至少一条端到端自动生产线。

### 灵石与商业系统

- 生产和交易空白灵石。
- 将空白灵石灌注、封灵为五行属性灵石。
- 实现下品、中品、上品和天品四个品级。
- 实现同属性灵石向下1:8、向上12:1的不对称兑换。
- 实现多属性、多品级混合支付。
- 加入商店、资源点聚灵阵和周期性灌注委托。
- 鼓励技术套利、品级套利、五行供需套利和代工经营。

完成标志：生产自用、天然灌注、委托代工和商业交易均可成为有效的发展方式。

### 任务与叙事基础

- 实现任务发布、条件触发、状态跟踪、完成、失败与恢复。
- 使用Banner、文字、对话和事件呈现宗门生活。
- 保存玩家选择、角色关系和关键世界事实。
- 支持多条任务线并存，并为未来多主线和支线影响保留扩展能力。
- 将内容数据与程序逻辑分离。

完成标志：一段包含探索、生产、选择与后果的完整章节可以通过内容配置完成。

### v1.0全流程制作与稳定化

- 完成内门弟子至宗门长老的全部主线内容。
- 完成弱探索、中等解谜和强主线的整体节奏。
- 埋入未来暗线所需、但不影响v1.0独立完整性的伏笔。
- 完成教程、数值平衡、性能、存档迁移和全流程软锁检查。
- 在发布候选阶段停止新增大型系统，只修复问题、补齐缺失内容和调整平衡。

完成标志：玩家能够从新存档开始抵达正式结局，过程中不存在已知的阻断性错误或不可恢复状态。

## v1.0：内门弟子至宗门长老

v1.0是第一个完整游戏版本，而不是技术演示。

必须具备：

- 从获得宅院和纸质炼器阵开始的完整开局。
- 从手工劳动到全自动五行生产网络的成长过程。
- 可支撑主流程的材料、炼器、灵石和商业系统。
- 一条从内门弟子成长为宗门长老的强主线。
- 服务主线节奏的弱探索内容。
- 需要理解游戏规则但不过度阻断流程的中等解谜内容。
- 一个能够独立成立的正式结局。

## v2.0：多结局与多主线

v2.0扩展玩家的道路选择，使不同决策能够通往不同主线与结局。

重点方向：

- 多条可完成的主线。
- 关键选择、互斥关系和长期后果。
- 与资源经营、宗门关系和角色立场相关的不同结局。
- 从旧存档继续时保持选择记录和因果一致。

## v3.0：多支线、探索与强解谜

v3.0让支线不再是互不相干的任务清单，而是能够彼此影响的因果网络。

重点方向：

- 多条支线读取并改变其他支线、主线、角色和资源状态。
- 中等强度的区域探索。
- 以五行、物流、灵石经济和任务信息为基础的强解谜内容。
- 支线失败、错过、补救与延迟后果。

## v4.0：天气、大事件与宗门联谊

v4.0使世界拥有不完全围绕玩家运转的周期和变化。

重点方向：

- 影响资源点、运输和阵法运行的天气系统。
- 会改变宗门生产、市场和人物行动的大事件。
- 可切换主线，以及切换行为产生的机会成本和后果。
- 与其他宗门的联谊、交流、竞争和合作活动。

## v5.0：暗线、复杂结局与修仙界大地图

v5.0扩展游戏尺度，并收束此前版本持续铺设的暗线。

重点方向：

- 跨越多个版本伏笔的暗线内容。
- 结合主线、支线、商业行为和世界状态的复杂结局。
- 修仙界大地图与跨区域资源、市场和宗门关系。
- 支持联网能力的B/S架构。
- 复用网页核心的Electron桌面套壳。

B/S和Electron属于交付架构目标，不得迫使游戏核心依赖特定运行环境。v1.0以前应保持模拟层与浏览器DOM分离、持久化入口可替换，但不提前建设v5.0才需要的服务端。

## 跨版本原则

- 每个大版本必须能够独立形成清晰的玩家体验，而不是只完成一批内部接口。
- 后续版本需要的扩展点应提前保留，但不得以未来需求为理由过早实现大型系统。
- 已发布存档必须通过显式迁移继续使用，禁止静默重置玩家资产。
- 动画、帧率和设备性能不得改变资源计算结果。
- 商业套利是正式玩法；只有无决策、无成本、可无限重复的封闭循环属于缺陷。
- 暗线可以提前埋设，但不得破坏早期版本结局本身的完整性。

## 路线图变更规则

- 文字澄清、验收细化和阶段排序调整可以直接更新本文档。
- 改变v1.0至v5.0的核心承诺，需要在提交说明中明确记录原因和影响。
- 路线图不使用日期制造虚假的确定性；发布日期应在具备可验证内容后另行决定。
